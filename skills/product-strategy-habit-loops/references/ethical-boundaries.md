# Ethical Boundaries

The Hook Model is a tool that can build or destroy; the responsibility is the creator's. Every habit-forming product must answer: **does this make users' lives better?**

## The Manipulation Matrix

Plot the product on two axes — does it materially improve the user's life, and would the maker use it?

| | Maker uses it | Maker doesn't |
|--|---------------|---------------|
| **Improves life** | **Facilitator** ✓ (the goal) | **Peddler** ⚠️ |
| **Doesn't improve life** | **Entertainer** | **Dealer** ✗ (don't build) |

- **Facilitator** — you use it and it helps; you'd recommend it to family; engagement correlates with positive outcomes.
- **Peddler** — helps users but you don't use it; risk is not understanding user needs → mitigate with deep research and humility.
- **Entertainer** — doesn't necessarily improve life but you use it; acceptable *if honest* about what it is and time spent is a conscious choice.
- **Dealer** — helps no one and you wouldn't use it; red flags: you wouldn't want your kids on it, the business model depends on user regret, success metrics conflict with wellbeing.

## Dark Patterns vs Ethical Engagement

| Dark pattern | Ethical engagement |
|--------------|--------------------|
| tricks users into actions | motivates toward *their* goals |
| hides costs/consequences | transparent about tradeoffs |
| exploits cognitive weakness | works *with* psychology |
| benefits only the company | mutual value |
| user feels regret after | user feels satisfied after |

Concretely: notifications — "you're missing out!" (dark) vs "your friend replied" (ethical); urgency — fake resetting timers vs genuine deadlines; investment — trapping data vs value users *want* to keep; social proof — fake reviews vs real testimonials.

## Protecting Vulnerable Users

Special care for children (developing impulse control), teens (identity/peer pressure), people with addiction history (avoid gambling-like mechanics), people in crisis (don't exploit negative states), elderly (clear, honest interfaces). Safeguards: for children — no social-pressure manipulation, no purchases without parental consent, no gambling mechanics; for addiction-prone loops — usage dashboards, break reminders, easy "take a break," no punishment for disengaging; for everyone — clear paths to disengage, honest value, no exploiting negative emotions.

## Team Questions

Before building: would we want our kids/parents using this *this way*? does the model require unhealthy habits? are we proud of it? During: are we testing for addictive potential? do success metrics align with wellbeing? are we giving users ways to moderate? After: do users report better lives? any concerning usage patterns? would we be comfortable with media coverage of our tactics?

## Ethical Practices

- **Transparency** — tell users what you're doing and why; meaningful notification controls, usage dashboards, easy opt-outs, data portability.
- **Incentive alignment** — subscription/success-based models where engagement = value delivered beat ad models where time = money regardless of value.
- **Guardrails** — time-based ("you've scrolled 30 min — break?"), behavior-based (confirmation/cool-off before regrettable actions), self-selected (let users set their own limits).

## Regulation

Current: children (COPPA, GDPR-K), dark patterns (FTC/EU — false urgency, hidden fees, hard cancellation), emerging addiction/loot-box rules. Heading toward more regulation of notifications, variable rewards, design for minors, transparency, and a right to disengage. Build ethical practices now, before they're mandated.

## The Long View

Ethics trades short-term engagement for long-term lifetime value, retention, brand trust, and lower regulatory risk. **The reputation test:** if a journalist wrote about your engagement tactics tomorrow, would you be proud? If not, reconsider. The goal of the Hook Model isn't addiction — it's helping people form habits that serve them.

## Checklist
- [ ] Serves the user's stated goals
- [ ] Comfortable explaining the tactic publicly
- [ ] User controls built in
- [ ] Vulnerable populations considered
- [ ] User success aligns with our success
- [ ] Users can easily disengage
- [ ] We'd want this feature in a product *we* use
- [ ] Optimizing for value, not just time spent
